# Debugging Notes — August 2026 Deployment

## Issue 1: `catch (Exception $e)` silently fails in PHP 8.4

### Symptom
Controller routes that should redirect on error return HTTP 500 instead.

### Root Cause
In PHP 8.x, when a namespaced file (e.g. `App\Controller\MessageController`) uses `catch (Exception $e)` without a `use Exception;` import at the top, PHP resolves `Exception` to `App\Controller\Exception` — which does not exist. Unlike PHP 7.x, PHP 8.x does **not** fall back to the global `\Exception` namespace for class references in catch clauses.

This means the catch block never matches, and exceptions propagate uncaught to Symfony's ExceptionListener, which converts them to 500 error responses.

### Affected Files (before fix)
- `src/Controller/MessageController.php`
- `src/Controller/VerificationController.php`

### Fix
Add `use Exception;` to the import block of each affected file.

### Verification
```php
namespace App\Controller;
// Without "use Exception;" — this catches App\Controller\Exception (non-existent)
// With "use Exception;" — this catches \Exception (correct)
```

## Issue 2: `@dataProvider` annotations ignored in PHPUnit 12

### Symptom
`ArgumentCountError: Too few arguments to function App\Tests\UI\NavigationTest::testActiveNavLinkMarkedWithAriaCurrent(), 0 passed`

### Root Cause
PHPUnit 12 dropped support for annotation-based metadata. The `@dataProvider navRouteProvider` annotation was silently ignored, so the test method received no arguments.

### Fix
Replace the annotation with a PHP 8 attribute:
```php
// Before:
/**
 * @dataProvider navRouteProvider
 */
public function testActiveNavLinkMarkedWithAriaCurrent(string $url, string $expectedLinkText): void

// After:
#[DataProvider('navRouteProvider')]
public function testActiveNavLinkMarkedWithAriaCurrent(string $url, string $expectedLinkText): void
```

Also add the import: `use PHPUnit\Framework\Attributes\DataProvider;`

### Affected Files
- `tests/UI/NavigationTest.php`

## Issue 3: MockHttpClient fake PGP key missing email UID

### Symptom
`/submit/{token}` returns HTTP 500 with "No public key found for the provided email address"

### Root Cause
`tests/Mock/MockHttpClient.php` returns `FAKE_KEY` — a PGP key block with no `uid` line. `PgpKeyService::keyHasEmailUid()` checks for `<email@domain>` pattern in the key block, so it rejected the key.

### Fix
Add a `uid` line to the fake key block:
```
uid           Test User <test@example.com>
```

### Affected Files
- `tests/Mock/MockHttpClient.php`

## Issue 4: testInvalidPassphrase stale assumption

### Symptom
`PgpSigningServiceTest::testInvalidPassphrase` failed with "Unexpected error during signing"

### Root Cause
The test comment stated: "Keys generated by init-pgp.sh use %no-protection (no passphrase)" and expected that a wrong passphrase would be silently ignored by GnuPG. In reality, the key is generated with `--with-passphrase`, making it passphrase-protected. The wrong passphrase causes `sign()` to fail at runtime.

### Fix
Updated the test to expect `AppException` when signing with a wrong passphrase against a passphrase-protected key.

### Affected Files
- `tests/Service/PgpSigningServiceTest.php`

## Issue 5: Git safe.directory warning

### Symptom
Composer or PHPUnit may emit a warning about "dubious ownership" when running as `www-data` inside the container.

### Fix
```bash
docker compose exec php bash -c "git config --global --add safe.directory /var/www/app"
```
